# Тренажери для тестувальників: де практикуватися безкоштовно

Теорію тестування можна прочитати за тиждень, але роботодавця цікавить інше: чи вмієте ви знайти баг, описати його так, щоб розробник відтворив з першого разу, скласти тест-кейси й перевірити API. Навчитися цього можна лише на практиці. На щастя, для цього не потрібен реальний проєкт: є десятки безкоштовних сайтів, створених спеціально для тренування тестувальників, — з навмисними помилками, «незручними» елементами й навчальними API.

У статті зібрано найкорисніші тренажери, розкладені за навичками, а наприкінці — план на 30 днів і поради, як перетворити практику на портфоліо.

> **Важливо.** Доступність сайтів ми перевіряли 1 та 4 листопада 2026 року. Навчальні сайти інколи переїжджають або закриваються — якщо посилання не відкривається, загляньте в підкатегорію [«Тренажери для тестувальників»](subcategory:qa-practice), де ми підтримуємо актуальний список.

## Як користуватися тренажерами

Найбільша помилка — бездумно клацати по сайту. Працюйте як на справжньому проєкті:

1. **Вивчіть продукт.** Пройдіть основні сценарії, запишіть, що вміє застосунок і для кого він.
2. **Складіть чек-лист або тест-кейси.** Для зручності — у [Qase](product:Qase), [TestLink](product:TestLink) чи навіть у таблиці.
3. **Тестуйте й фіксуйте дефекти.** Кожен баг — з кроками відтворення, очікуваним і фактичним результатом та скриншотом. Для запису зручно взяти [Jam](product:Jam) чи [Monosnap](product:Monosnap).
4. **Перевірте API та базу**, якщо тренажер це дозволяє.
5. **Підсумуйте:** короткий звіт про тестування з тим, що перевірено, що знайдено й що варто перевірити ще.

Ці тренажери створено саме для мануального тестування: помилки в них закладено свідомо, і ваше завдання — знайти якомога більше.

## Полігони з «незручними» елементами

Тут кожна сторінка — окрема типова проблема: динамічні ідентифікатори, iframe, спливні вікна, перетягування, завантаження файлів, елементи, що з'являються із затримкою. Мануальному тестувальнику ці сторінки показують, де найчастіше ховаються дефекти, а майбутньому автоматизатору — що доведеться автоматизувати.

- **[The Internet](product:The Internet)** (Herokuapp) — понад 40 класичних прикладів, з яких починали тисячі автоматизаторів.
- **[DemoQA](product:DemoQA)** — форми, віджети, вікна, перетягування й книжковий магазин з API.
- **[UI Test Automation Playground](product:UI Test Automation Playground)** — пастки UI-автоматизації: динамічні ID, приховані шари, затримки AJAX.
- **[Expand Testing Practice](product:Expand Testing Practice)**, **[LetCode](product:LetCode)**, **[WebDriverUniversity](product:WebDriverUniversity)**, **[Bondar Academy Playground](product:Bondar Academy Playground)**, **[TestKru](product:TestKru)**, **[GlobalSQA Demo Site](product:GlobalSQA Demo Site)** — великі полігони для Selenium, Playwright і Cypress.
- **[Practice Test Automation](product:Practice Test Automation)** і **[Rahul Shetty Academy Practice Page](product:Rahul Shetty Academy Practice Page)** — прості сторінки для найпершої практики.

## Тестові API

На цих сервісах можна вільно надсилати запити з [Postman](product:Postman), [Bruno](product:Bruno) чи [Hoppscotch](product:Hoppscotch), не боячись щось зламати:

- **[ReqRes](product:ReqRes)** і **[JSONPlaceholder](product:JSONPlaceholder)** — найпростіший старт: реальні відповіді без реєстрації.
- **[Restful-Booker](product:Restful-Booker)** — API бронювань з авторизацією й навмисними помилками; дані скидаються кожні 10 хвилин.
- **[Swagger Petstore](product:Swagger Petstore)** — демо-API з документацією Swagger UI, де запити можна надсилати прямо з браузера.
- **[GoRest](product:GoRest)** — токени, пагінація й специфікація OpenAPI, як у справжніх проєктах.
- **[Fake Store API](product:Fake Store API)** і **[DummyJSON](product:DummyJSON)** — дані інтернет-магазину, авторизація, пошук.
- **[httpbin](product:httpbin)** повертає те, що ви надіслали, — зручно розбиратися з методами, заголовками, кодами статусу й затримками.

Для перевірки відповіді на синтаксис допоможе **[JSONLint](product:JSONLint)**.

## Як перетворити практику на портфоліо

Роботодавцю набагато цікавіше побачити вашу роботу, ніж прочитати «знаю теорію тестування». Зберіть у публічному репозиторії на GitHub або в документі:

- тест-кейси й чек-лист для одного з тренажерів;
- 5–10 якісних баг-репортів зі скриншотами чи відео;
- колекцію Postman для тестового API;
- короткий звіт про тестування;
- за бажанням — кілька автотестів на Playwright чи Selenium.
