# Реклама: експлуатація (cron, пошта, перевірка посилань)

Доповнення до `docs/PROMO_SYSTEM.md` (блоки F–I, 2026-10-12). Хостинг — adm.tools,
акаунт `gu621051`, корінь проєкту `/home/gu621051/ailabhub-directory.com/www/`
(веб-корінь — `www/public/`, тож `www/cron/` з браузера недоступний).

> **Звірте шляхи з панеллю хостингу.** Шлях до проєкту взято з наявних нотаток
> про хостинг; шлях до PHP CLI залежить від версії PHP, обраної в панелі.

## 1. Розклад cron

adm.tools → хостинг-акаунт → **«Планувальник завдань» (Cron)** → «Додати завдання».
Для кожного рядка: команда, частота. Версія PHP — та сама, що в сайту (8.x).

| Завдання | Частота | Команда |
|---|---|---|
| Відправка листів | кожні 5 хв (`*/5 * * * *`) | `php /home/gu621051/ailabhub-directory.com/www/cron/promo-mail.php` |
| Щогодинні дії | щогодини (`7 * * * *`) | `php /home/gu621051/ailabhub-directory.com/www/cron/promo-hourly.php` |
| Щоденне обслуговування | о 03:10 за Києвом | `php /home/gu621051/ailabhub-directory.com/www/cron/promo-daily.php` |
| Щотижневі перевірки | раз на тиждень (напр. неділя 04:20) | `php /home/gu621051/ailabhub-directory.com/www/cron/promo-weekly.php` |

- Якщо панель просить повний шлях до PHP, підставте його замість `php` (його
  показує сама панель або підтримка; типові варіанти — `/usr/local/bin/php`,
  `/opt/alt/php83/usr/bin/php`).
- **03:10 за Києвом:** якщо панель приймає час за Києвом — `10 3 * * *`. Якщо сервер
  cron працює в UTC: `10 1 * * *` (узимку, UTC+2) або `10 0 * * *` (улітку, UTC+3).
  Зсув на годину не критичний: «доба» в коді рахується за Europe/Kyiv, завдання лише
  має запускатися раз на добу вночі.
- Старий `public/promo-cron.php` лишається (сумісність), але тепер його роботу робить
  `cron/promo-daily.php` — окремо його ставити не треба.
- Скрипти не запускаються паралельно (flock у `storage/locks/`), пишуть журнал у
  `storage/logs/cron.log` (ротація > 1 МБ → `cron.log.1`) і в таблицю `cron_runs`.
- Перевірка: адмінка → «Реклама: адмін» → **«Стан»**: останній запуск кожного
  завдання; червоне попередження, якщо завдання не запускалось довше за очікуване.

## 2. Пошта

Листи лише транзакційні (модерація, старт, зупинка, баланс, поповнення; адміну —
нові креативи, заявки, скарги, автопауза). Сайт кладе листи в `mail_queue`,
відправляє `cron/promo-mail.php` (до 5 спроб із паузою 5 / 15 / 60 / 240 хв).

### 2.1. Скринька hello@

1. adm.tools → **Пошта** → домен `ailabhub-directory.com` → створіть (або використайте
   наявну) скриньку `hello@ailabhub-directory.com`, задайте пароль.
2. Там само подивіться параметри SMTP (сервер, порт 465/SSL або 587/TLS).
3. Відповіді на листи йдуть на `partners@ailabhub-directory.com` — переконайтеся,
   що ця скринька (чи переадресація) існує.

### 2.2. config/mail.php

У файловому менеджері: `www/config/mail.example.php` → скопіюйте як `www/config/mail.php`,
відкрийте й впишіть `host`, `port`, `encryption`, `username` (повна адреса), `password`.
Файл не в git і не перезаписується архівами деплою. Без нього (чи з порожнім `host`)
використовується PHP `mail()`. `transport => 'log'` — тестовий режим без відправки
(листи пишуться в `storage/logs/mail-dryrun.log`).

### 2.3. SPF, DKIM, DMARC

adm.tools → **Домени** → `ailabhub-directory.com` → **DNS-записи**:

- **SPF** — TXT для `@`: якщо пошта на adm.tools, зазвичай панель уже має запис
  `v=spf1 include:… ~all`; перевірте, що він один (два SPF-записи ламають перевірку).
- **DKIM** — у розділі пошти домену ввімкніть DKIM-підпис; панель створить TXT-запис
  (`…._domainkey`). Якщо не створила автоматично — додайте вручну з показаного значення.
- **DMARC** — TXT для `_dmarc`: почніть м'яко
  `v=DMARC1; p=none; rua=mailto:partners@ailabhub-directory.com`, через кілька тижнів
  без проблем можна посилити до `p=quarantine`.

Зміни DNS поширюються до кількох годин.

### 2.4. Перевірка доставки

1. Тимчасово додайте свою адресу в `admin_emails` у `config/mail.php` або зробіть
   тестову дію (наприклад, заявку на поповнення з тестового акаунта).
2. Дочекайтеся запуску `promo-mail` (до 5 хв) → «Стан»: лист `sent`.
3. У поштовій скриньці відкрийте «Показати оригінал» / заголовки: `spf=pass`,
   `dkim=pass`, `dmarc=pass`. Перевірте, що лист не в спамі.

## 3. Safe Browsing / Web Risk

Без ключа перевірка посилань працює (статус, редиректи, домени, скорочувачі, чорний
список), але **без перевірки на шкідливі сторінки** — модератор бачить попередження.

- **Safe Browsing Lookup API v4** — безкоштовний, але за умовами Google призначений для
  **некомерційного** використання.
- **Web Risk API** — комерційний варіант Google (платний понад безкоштовну квоту).
  Умови й ціни перевірте на сайті Google Cloud перед вибором.

Отримати ключ: Google Cloud Console → створіть проєкт → «APIs & Services» → увімкніть
«Web Risk API» (або «Safe Browsing API») → «Credentials» → «Create credentials → API key»
→ обмежте ключ цим API. Впишіть у `www/config/promo.php`:

```php
'safe_browsing' => ['provider' => 'web_risk', 'api_key' => 'ВАШ_КЛЮЧ'],   // або 'safe_browsing'
```

## 4. Якщо щось не працює

**Cron не запускається** («Стан» червоний):
- перевірте в панелі, що завдання є й увімкнені, шлях до PHP і скрипта правильний;
- у панелі зазвичай є журнал виконання — помилка «not found» означає неправильний шлях;
- `storage/logs/cron.log` — є рядки з часом запуску? `SKIPPED` — попередній запуск
  ще йде (або завис: файл `storage/locks/<job>.lock` звільняється сам після завершення процесу);
- `ERROR …` у «Стан» — текст помилки (часто — міграцію не застосовано).

**Пошта не доходить:**
- «Стан» → «Листи з помилкою»: `SMTP Error: Could not authenticate` — логін/пароль;
  `Could not connect` — сервер/порт/шифрування (465+ssl або 587+tls);
- транспорт `log` — це тестовий режим, змініть на `smtp`;
- листи `sent`, але їх немає — дивіться спам і SPF/DKIM/DMARC (розділ 2.3–2.4);
- черга росте, а «promo-mail» не запускається — див. «Cron не запускається».

**Перевірка посилань:** вкладка «Перевірка посилань» — останні перевірки й журнал подій.
`ssrf_blocked` — адреса веде у внутрішню мережу або на недозволений порт (так задумано).
