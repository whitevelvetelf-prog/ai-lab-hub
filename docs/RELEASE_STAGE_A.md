## Порядок: SQL → файли → конфіг → перевірки

### Крок 0. Резервна копія (5–10 хв, обов'язково)

1. **База.** adm.tools → Бази даних → рядок `gu621051_ailabhublive` → «Увійти».
   У phpMyAdmin клацніть назву бази зліва → «Експорт» → «Швидкий» → «SQL» → «Вперед».
   Збережіть файл на комп'ютер і підпишіть датою, наприклад `hosting-2026-11-23.sql`. Цей файл також стане `backups/hosting-baseline.sql`.
2. **Конфіги.** Файловий менеджер → `www/config/` → завантажте собі `marketplace.php` і `marketplace.local.php`.
   **Не відкривайте їх у чатах і не надсилайте**: там секрети.
3. **Код.** Нічого робити не треба: відкат коду — це попередній архів (див. «Відкат»).

### Крок 1. SQL (лише новий сайт, 5 хв)

Живому сайту цей крок **не потрібен**: усе вже застосовано.

1. phpMyAdmin → база `gu621051_ailabhublive` → «Импорт».
2. Виберіть файл `marketplace-ALL-04-28-part1.sql` → «Вперед».
3. У кінці результатів має бути рядок **«OK частина 1»**.
   Якщо замість нього з'явилась помилка «ПОМИЛКА_потрібна_MySQL_5.6.5_або_MariaDB_10.0», версія бази застара: зупиніться.
4. **Ніколи** не імпортуйте `database/schema.sql` і `database/seed.sql`: вони стирають таблиці.

### Крок 2. Файли коду (10–15 хв)

1. Файловий менеджер adm.tools → тека `ailabhub-directory.com/` (на рівень вище за `www`).
2. «Завантажити файли» → `deploy-mp.zip`.
3. Поставте галочку біля архіву → **Shift + 7** (розпакувати) → у полі призначення впишіть `www` → ✓.
   Архів містить лише файли, тому права тек `app/` і `config/` не змінюються.
4. Перевірте права: `www/app` і `www/config` мають бути **750**.
   Якщо стало 775, виправте: Ctrl+1 → значок прав → 750, без «рекурсивно».
5. Видаліть `deploy-mp.zip` з `ailabhub-directory.com/`.

### Крок 3. Конфіг (лише новий сайт або свідоме повернення до етапу A, 5 хв)

1. Відкрийте `marketplace.config.HOSTING.stageA.php` у блокноті.
2. Розкоментуйте рядки з позначкою **ЗАПОВНЮЄ ВЛАСНИК** (приберіть `//` на початку) і впишіть:
   - `site_url` → `https://ailabhub-directory.com`;
   - `cron_token` і `rate_limit_salt` → токени з `gen-token.php`;
   - `file_storage_dir`, `photo_dir` → як у шаблоні.
   Рядок, який лишається порожнім, **не розкоментовуйте**: порожнє значення затирає серверне.
3. Збережіть файл як `marketplace.local.php` і залийте в `www/config/`.
   Для живого сайту замість цього відкрийте наявний `www/config/marketplace.local.php` (правий клік → «Відкрити»)
   і змініть **лише** потрібні прапори → «Зберегти та вийти».
4. **Соцмережі в підвалі (за бажанням, і для живого сайту):** відкрийте `config/social.php` з репозиторію, у рядку
   `'facebook'` замініть `[ВСТАВТЕ ПОСИЛАННЯ]` на адресу сторінки (`https://www.facebook.com/…`) і залийте файл у
   `www/config/`. Архів коду цей файл не містить. Немає файла чи посилання — кнопки немає. Інші мережі додавайте обережно:
   уже з трьома значками мобільний підвал на ширині 390 px стає вищим на 50 px.
5. Кабінет адміністратора → блок «Marketplace для відвідувачів» має показувати «показується» (інакше — кнопка «Показати відвідувачам»).

### Крок 4. Перевірки з комп'ютера (5 хв)

```
powershell -ExecutionPolicy Bypass -File scripts/smoke-test.ps1 https://ailabhub-directory.com --stage=view --delay=1
```

Очікувано: **FAIL 0**, код виходу 0. Звіт лежить у `storage/smoke-report-РРРРММДД-ГГХХ.txt`.
Якщо хоч один FAIL — відкрийте звіт, рядок FAIL пояснює, що саме не так.
Для живого сайту з відкритою подачею замість `view` використовуйте `--stage=open`.

Потім: Кабінет (адміністратор) → «Стан сайту». Усі рядки мають бути «налаштовано» або «вимкнено». «Не налаштовано» означає, що поле в конфігу не заповнене.

### Крок 5. Перевірки з iPhone (10 хв, Safari, без входу й потім з входом)

1. `ailabhub-directory.com/marketplace.php`: є блоки, картки відкриваються, фото показуються.
2. Пошук у Marketplace за будь-яким словом показує результати.
3. Сторінка оголошення: «Показати контакт» без входу просить увійти.
4. Етап A: «Подати оголошення» для звичайного користувача каже, що подача відкриється згодом.
   Якщо подача відкрита — це стан етапу B, як зараз на живому сайті.
5. Увійдіть → Кабінет відкривається, нижнє меню не перекриває кнопки.
6. Перемкніть мову на EN: тексти англійською.
7. Підвал і шапка на телефоні в один рядок, кнопки «Назад» і «Поділитися» є.

### Крок 6. Завершення (2 хв, на комп'ютері)

```
git tag deployed-РРРР-ММ-ДД
powershell -ExecutionPolicy Bypass -File scripts/release-manifest.ps1 -Zip hosting-upload/code/deploy-mp.zip
```

У тегу — дата заливки, наприклад `deployed-2026-11-23`. Тег лишається локальним (не надсилайте у віддалений репозиторій, доки репозиторій публічний).
`RELEASE_MANIFEST.txt` після цього відповідає залитому архіву: збережіть його поруч із резервною копією.

## Що НЕ заливати на хостинг

- `config/*.php` з комп'ютера (`database.php`, `translation.php`, `oauth.php`, `mail.php`, `promo.php`, `ai-assistant.php`, `*.local.php`):
  на сервері свої файли із секретами. Архів їх не містить.
- `storage/`, `backups/`, `scripts/`, `tests/`, `tools/`, `marketplace-seed/`, `hosting-upload/`, `.git/`, `.env*`.
- `database/schema.sql`, `database/seed.sql`, `database/export_live*.sql`, будь-які дампи.
- `public/_*.php` (разові діагностичні сторінки).
- Самі файли `marketplace.config.HOSTING.stage*.php`: це шаблони, на сервер іде лише `marketplace.local.php`, складений із шаблону.

Перевірка, що архів чистий: `scripts/release-manifest.ps1`. Якщо в архіві є щось заборонене, скрипт завершиться з помилкою.
