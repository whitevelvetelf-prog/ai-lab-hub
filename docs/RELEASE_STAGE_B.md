# Реліз Marketplace, етап B: подачу оголошень відкрито для всіх

Етап B іде після етапу A (`docs/RELEASE_STAGE_A.md`). Від етапу A він відрізняється одним прапором: `posting_enabled = true`.
Повідомлення й листи лишаються вимкненими.

> ## ⚠ Стан живого сайту (2026-11-22)
>
> На ailabhub-directory.com подачу вже відкрито з 2026-09-28: етап B фактично діє, хоча умови нижче виконано не всі.
> Крім того, там увімкнено повідомлення (`messaging_enabled = true`). Шаблон `marketplace.config.HOSTING.stageB.php`
> їх **вимикає**, тож для живого сайту не замінюйте файл, а змінюйте лише потрібні прапори в наявному
> `www/config/marketplace.local.php`.
> Умови нижче — список, що треба довести до кінця, щоб відкрита подача відповідала плану релізу.

## Що потрібно перед початком

Те саме, що для етапу A, плюс шаблон `hosting-upload/marketplace.config.HOSTING.stageB.php`.

## Порядок: SQL → файли → конфіг → перевірки

### Крок 0. Резервна копія (5–10 хв)

Так само, як крок 0 етапу A: експорт бази в phpMyAdmin і копії `www/config/marketplace.php` та `marketplace.local.php`.

### Крок 1. SQL (2 хв)

Нових міграцій етап B не потребує. Якщо ще не застосовано:

1. `database/migration-2026-11-22-mp-platform-promos-ui.sql` (№ 29) — у phpMyAdmin → «Импорт». У результаті має бути «OK міграція 29».
2. За бажанням — оголошення платформи `hosting-upload/promos-seed.sql` (`docs/PROMO_LISTINGS.md`).

### Крок 2. Файли коду (10–15 хв)

Так само, як крок 2 етапу A. Архів збирайте **після** виконання умови 1: з `posting_enabled = true` збірка
зупиняється, якщо в Правилах знову з'явилися маркери.

### Крок 3. Конфіг (5 хв)

1. Відкрийте `www/config/marketplace.local.php` у файловому менеджері (правий клік → «Відкрити»).
2. Поставте `'posting_enabled' => true,`. Решту прапорів не змінюйте, якщо не вирішили інакше.
3. «Зберегти та вийти».

Для нового сайту візьміть шаблон `marketplace.config.HOSTING.stageB.php` і заповніть рядки **ЗАПОВНЮЄ ВЛАСНИК**, як в етапі A.

### Крок 4. Перевірки з комп'ютера (5 хв)

```
powershell -ExecutionPolicy Bypass -File scripts/smoke-test.ps1 https://ailabhub-directory.com --stage=open --delay=1
```

Очікувано: **FAIL 0**. Потім Кабінет → «Стан сайту»: рядок «прапори» має показувати «posting увімкнено».

### Крок 5. Перевірки з iPhone (15 хв)

1. Без входу: «Подати оголошення» просить увійти.
2. Новий акаунт без підтвердженої пошти: форма просить підтвердити пошту.
3. Після підтвердження: подати оголошення з фото → «на модерації».
4. З іншого пристрою, як адміністратор: CRM → черга → схвалити → оголошення видно в блоці, лічильник збільшився.
5. Оголошення має строк 90 днів; «Продовжити» стає доступним ближче до кінця строку.
6. Видалити тестове оголошення й тестовий акаунт (CRM; або SQL лише за id).

### Крок 6. Завершення

```
git tag deployed-РРРР-ММ-ДД
powershell -ExecutionPolicy Bypass -File scripts/release-manifest.ps1 -Zip hosting-upload/code/deploy-mp.zip
```

Тег локальний. `RELEASE_MANIFEST.txt` зберегти поруч із резервною копією.
